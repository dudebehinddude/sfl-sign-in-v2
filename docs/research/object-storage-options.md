# Object storage alternatives

Researched **2026-11-09, approximately 16:12 UTC**. Research only: no app, Compose, image, volume, credentials, or running storage were changed. The current candidate's pinned older MinIO build and successful JPEG put/get check remain intact. Upstream MinIO's repository is archived as of April 25, 2026; preserving its old console does not provide ongoing upstream maintenance. [Upstream repository](https://github.com/minio/minio).

## Recommendation for SFL

**Evaluate PGSTY Silo first. SeaweedFS `weed mini` is an independent alternative only after a console trial: upstream explicitly marks its Admin UI as work in progress.** Silo is an actual maintained server-and-console fork, rather than an old UI attached to an unmaintained server. Its October 26 server release embeds the full Console 2.5.1 and preserves MinIO compatibility. This makes it the smallest conceptual change for the lab's existing S3 adapter and familiar management workflow. This recommendation is an assessment of fit, not a completed runtime acceptance test. [Verified server release](https://github.com/pgsty/silo/releases/tag/RELEASE.2026-10-26T00-00-00Z), [compatibility audit](https://silo.pgsty.com/compatibility/server/).

For a fresh deployment where MinIO lineage and console familiarity do not matter, **SeaweedFS** deserves a storage-engine trial, but its production history does not establish a mature, complete console. Its November 5 Admin UI documentation warns that it is work in progress and that some features do not work. Bucket, user, policy and file workflows are documented, but their actual coverage remains unverified. [Upstream UI warning](https://github.com/seaweedfs/seaweedfs/wiki/Admin-UI). The project maintains a [public adopter list](https://github.com/seaweedfs/seaweedfs/wiki/Actual-Users); that is reported storage-deployment evidence, not an independent reliability audit or console acceptance test. RustFS is credible and has a good console, but its first stable 1.0.0 release was only September 16, 2026. Garage is attractive for small distributed storage, but requires a separately maintained UI to meet this user's management requirement. [RustFS 1.0.0](https://github.com/rustfs/rustfs/releases/tag/1.0.0), [Garage project history](https://github.com/deuxfleurs-org/garage).

## Compatibility with the actual app

The current [storage adapter](../../backend/app/services/storage.py) uses `minio-python` for `HeadBucket`, explicit `CreateBucket`, `PutObject` and `GetObject`. It uploads re-encoded JPEGs under `avatars/<key>` and stores only `<key>` in `users.avatar_key`. The browser receives avatars through the app; it needs neither public bucket access nor direct S3 credentials.

Silo preserves the protocol lineage; RustFS explicitly documents MinIO SDK compatibility. Garage and SeaweedFS document the required core operations. This supports retaining the current SDK and database model, subject to an actual adapter acceptance run against a pinned candidate. Do not interpret "S3-compatible" as complete AWS or MinIO administrative compatibility. Garage, for example, documents missing bucket versioning and bucket-policy endpoints. [RustFS SDK compatibility](https://docs.rustfs.com/en/developer/sdk), [Garage operation matrix](https://garagehq.deuxfleurs.fr/documentation/reference-manual/s3-compatibility/), [SeaweedFS operation matrix](https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API).

A later migration should create a fresh candidate bucket, copy objects through S3, preserve keys/content types, compare object counts and downloaded bytes, and test the app's JPEG upload/read/missing-object behavior. Keeping identical keys avoids a user-table migration. Different engines cannot reuse MinIO's raw data directory. Although Silo documents storage-format compatibility, copying this small bucket is a simpler rollback boundary than immediately upgrading its only volume in place. Endpoint, credentials, region and provisioning configuration would change; the public avatar route can stay. [Silo migration guidance](https://silo.pgsty.com/compatibility/migration/).

## Deployment, resources and administration

All four server candidates have a documented container path. Actual avatar-workload RAM consumption was not measured here, and comparable small-instance minimums were not established. RustFS currently lists **1 GB+ for testing** and a much larger **64 GB+, four-node production configuration**. Those are its published scenarios, not proof that an avatar-only server needs 64 GB or that a 1 GB production limit is safe. Measure the selected single-host candidate with a memory limit and representative images. [RustFS hardware guidance](https://docs.rustfs.com/en/installation/requirement/checklists/hardware-selection).

The app's `superadmin` role does not automatically protect any vendor console. Keep S3 and other service ports on the private Compose network, give the app a bucket-scoped key, and restrict the console's complete UI/API/WebSocket paths through the app's superadmin authorization boundary. Keep vendor administrator credentials separate. Garage UI documents subpath support, and SeaweedFS documents a URL prefix; the selected console's login, redirects and sockets still need an integration check before promising same-origin hosting. [Garage UI proxy support](https://github.com/Noooste/garage-ui#serving-from-a-subpath), [SeaweedFS proxy/auth configuration](https://github.com/seaweedfs/seaweedfs/wiki/Admin-UI).

A beta instance should have its own Compose project, storage volume, bucket credentials and internal network, with only its existing app-facing port changed. Reusing host-published console ports would defeat the one-port-instance setup. This is a proposed deployment shape, not an implemented change.

## Release and security findings that affect selection

- **Silo release streams differ.** Direct GitHub API checks verified server October 26 with embedded Console 2.5.1, and standalone Console **2.7.0 published November 9 at 12:39:47 UTC**. Updating a standalone console does not update the embedded one. Main's README advertises a November 9 server tag that was not available during this check; the server latest-release API still returned October 26. Recheck before pinning rather than copying main's example. [Server release API](https://api.github.com/repos/pgsty/silo/releases/latest), [Console release](https://github.com/pgsty/silo-console/releases/tag/v2.7.0), [main README](https://github.com/pgsty/silo/blob/main/README.md).
- **Security evidence needs version-specific reading.** RustFS's presigned-header advisory identifies 1.0.0 as patched. SeaweedFS's IAM gRPC advisory still lists no patched version, while the actual 4.53 source now calls an authorization guard on those handlers. That confirms a source change, not a complete audit or proof that every advisory is closed. Its internal gRPC endpoints must not become general LAN administration endpoints. [RustFS advisory](https://github.com/rustfs/rustfs/security/advisories/GHSA-g8w9-qw9q-fghr), [SeaweedFS advisory](https://github.com/seaweedfs/seaweedfs/security/advisories/GHSA-5fx4-c9qp-36jc), [4.53 source](https://github.com/seaweedfs/seaweedfs/blob/4.53/weed/s3api/s3api_server_grpc.go).
- **Silo publishes a separate security ledger.** An empty GitHub advisories list does not mean there are no security changes to review. Only its current release line is supported under its policy. [Security policy](https://github.com/pgsty/silo/blob/main/SECURITY.md), [advisory ledger](https://silo.pgsty.com/about/security-advisories/).

## Remaining decisions and evidence gaps

1. Choose whether familiarity with the complete MinIO console favors Silo, or whether leaving that code lineage justifies a SeaweedFS trial despite its explicitly unfinished console. Neither requires blocking current app integration.
2. Confirm the management tasks the user actually wants beyond object browsing: user/key/policy management, usage, retention/versioning, or server operations. This determines console acceptance, not avatar throughput.
3. Before any replacement, test the pinned candidate's actual `minio-python` operations, private-bucket behavior, authenticated console path, restart persistence, backup/restore and beta isolation. Real runtime compatibility, resource use and long-term maintainer continuity remain unverified.
