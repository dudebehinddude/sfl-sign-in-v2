## Constraints

## Frontend routing options

A. Vite + TanStack Router file routes + TanStack Query, feature modules, generated OpenAPI TS types and domain query keys. Compatible with user's Next-like routing request while keeping Vite/FastAPI. Reference T3 Code's structural conventions, not its desktop-specific machinery.
B. Vite + React Router framework/library file routes. Familiar, fewer bespoke route patterns, but compare type-safe integration and generation needs.
C. Next.js frontend would violate explicit create-vite-app request unless user later approves. Do not choose now.

## Operator admin options

A. One custom shadcn operator UI using TanStack Table/forms + explicit FastAPI domain services. RBAC and same event/query clients across kiosk, public occupancy, staff. Domain-specific actions clearer than autogenerated table edits. Moderate extra CRUD work, full control over behavior/accessibility.
B. Refine headless admin/data/auth/live providers with shadcn. Useful CRUD framework and access control integration, extra abstraction/provider contracts; server authorization still mandatory. Official docs https://refine.dev/core/docs/.
C. React Admin / Shadcn Admin Kit. Mature resource admin, verify actual edition/licensing and realtime support before choosing. Official docs https://marmelab.com/react-admin/.
D. SQLAdmin as internal maintenance UI, not main public/staff frontend. Faster server-side CRUD but duplicates UI/auth concerns; does not itself provide desired SQL client experience.
Decide best implementation for now and explain alternatives, don't install every option.

## Backend, realtime, jobs options

A. Modular FastAPI monolith + PostgreSQL + one lightweight worker sharing services; transactional outbox/events + PostgreSQL LISTEN/NOTIFY for post-commit cross-process wakeups. Persist events/jobs, sequence/revision and reconnect snapshot. Websocket subscribes before loading/sending snapshot or resnapshots on revision gap; ordered event IDs bounded retention; authoritative snapshot on every reconnect. Notifications are invalidation hints, not durable queue. Authenticated private events must never reach public occupancy channel. No required Redis broker. HTTP command endpoints and websocket command envelope call same application services and permissions.
B. FastAPI + Redis Streams/pubsub + Celery/Dramatiq. Mature worker ecosystem, more services/operations; raw pubsub alone loses reconnect events and does not prove durable state.
C. Socket.IO on FastAPI. Provides reconnection/rooms but still requires durable jobs, permission rechecks and consistent snapshots; adds protocol/client dependency.
Favor simplest that actually preserves commit ordering, reconnect correctness and multiple workers. Don't replace consistency with frontend polling. Single process in-memory demo hub alone is insufficient for production architecture; if first implementation limited, make gaps explicit and test real Postgres path.

## Proposed schema for approval

All names snake_case, UUID internal PK unless natural immutable enum key; timestamptz UTC for timestamps. created_at/updated_at on mutable entity and relation tables. Named string enums. External/student identifiers are opaque strings, not arithmetic ints. Explicit FKs, unique constraints, checks and indexes. Permission roles distinct from physical access.

- users: id, first_name, last_name, email, normalized_email, avatar_file_id, physical_access_level enum, keyholder_priority >= -1 default -1, active; timestamps. Avoid global unique email before knowing shared/external accounts; council decide matching constraints.
- user_identifiers: id, user_id FK, provider enum student_id/canvas_id/etc, value, normalized_value, verified_at, timestamps; unique(provider,normalized_value). Real Canvas IDs can belong to synced roster before local user exists; distinguish external identities below from local binding, prevent conflicting reassignments.
- accounts/auth_sessions: explicit login credential hash and server-side sessions, auth roles/permissions, expiry/revocation. No authentication by knowing a Niner ID. Kiosk tap identification is NOT staff authentication. Superadmin bootstrap command, never default production password. Physical access enum not authority to execute SQL.
- roles, permissions, user_roles, role_permissions: catalog names/enums, no privilege escalation by admin grant. Superadmin reserved capabilities only, including SQL and role/grant changes; ordinary admins can permitted user/training/visit actions. Evaluate whether fixed role presets plus individual grants simpler than arbitrary editable roles for now.
- training_types: id, name, slug, description, icon_key, active, timestamps; definition distinct from completed user training.
- certifications: id, user_id, training_type_id, level enum apprentice/operator/trainer/certifier, awarded_by_user_id nullable, awarded_at, expires_at nullable, revoked_at nullable, source enum manual/canvas/import, source_record_id, timestamps. Record history/audit and define current effective highest active level. Don't replace all history with nested user object or overwrite manual higher cert on sync.
- canvas_roster: id, canvas_user_id unique, normalized_email, display_name, raw source payload only in admin/internal storage, user_id nullable unique binding, last_seen_at, last_synced_at, timestamps. Supports roster before first tap.
- canvas_assignment_mappings: id, training_type_id, course_id, assignment_id, passing_score/grade rule, enabled, timestamps; do not hardcode quiz IDs in code.
- canvas_results: id, roster_id, mapping_id, workflow_status, score/grade/pass, completed_at, fetched_at, timestamps; unique(roster_id,mapping_id) or attempt-aware if API provides attempt. Sync must preserve failed/unknown vs genuine missing.
- visits: id, user_id, started_at, ended_at nullable, closure_reason enum tap/space_close/forgot/manual, purpose enum optional club/class/senior_design/personal/other, timestamps; one open visit/user via partial unique index, ended_at>=started_at; no redundant still_in_space flag. Generated stored duration or query-computed expression from timestamps, council choose and explain. Open duration derived on read; reporting clips intervals into requested date window, incomplete/forgotten handling explicit.
- keyholder_shifts: id, user_id, started_at, ended_at, timestamps; current legacy ownership, opening/handoff priority and closing semantics preserved pending live snapshot. At most one open shift via singleton partial unique index. No new keyholder rules.
- files: id, storage_key, mime_type, size, created_at, updated_at; validate profile images, public avatar endpoint exposes only intended asset.
- print_jobs: id, user_id, visit_id, label_payload snapshot, state enum pending/claimed/printed/failed/uncertain, attempts, lease_expires_at, last_error, printed_at, printer_id, timestamps. Durable queue, authenticated printer device, explicit uncertain retry semantics, no falsely exactly-once guarantee. Printing status independent of visit commit.
- sync_runs: id, provider, status, started_at, finished_at, counts, last_error, timestamps, last success distinguish transient failure; server-side secrets via env only.
- audit_events: id, actor_user_id, action enum/string, entity_type/id, before/after redacted JSON, occurred_at, request_id; append-only, do not log password/session/token/SQL result content indiscriminately.
- change_events/outbox: monotonic id, event_type, audience enum public/staff/device, entity id, payload minimized, occurred_at; commit with domain changes; durable wakeup/replay or snapshot recovery. Private user edits must invalidate public projections without exposing private payload.

Avoid implementing every optional table if smaller equivalent maintains requirements. Identify needed vs future before schema lock.

## SQL workbench

Server-enforced superadmin only. Table/schema browser, column metadata, paginated rows, SQL editor with result grid, row count/time/errors, CSV export, transaction status. Read query default in actual database read-only transaction with timeout/row cap. Explicit write execution mode/confirmation for intentionally powerful superadmin; no regex-based fake SQL security. Separate controlled connection/role and structured audit, authenticate every request and websocket action. Do not expose SQL to staff/admin role even if they manipulate frontend. Do not publish database port. A native external SQL client requires a PostgreSQL connection/tunnel, not merely an HTTP bearer token; defer optional BYO-client integration.

## Security/correctness cases to settle

- Public occupant payload minimal; photo URLs safe; no auth needed for read only. LAN isn't authentication for staff writes. Kiosk writes require provisioned device identity/session, scanner IDs aren't passwords. How to provision browser kiosk in local dev without hidden credentials? Document one-time bootstrap pairing and separate admin auth.
- Idempotency key for retries (tap can toggle twice otherwise), per-user transaction serialization + partial unique open visit. Close/handoff races serialize same lab lock; worker never holds tap lock for network.
- WS origin/session checks, CSRF for cookie mutation routes, role changes/revocations invalidate/recheck private subscriptions. Bounded resnapshot after disconnect prevents stale list.
- Metrics time windows, current open visits, forced closure exclusion, DST timezone, sessions overlapping boundaries. Define denominator for average and unique visitor inclusion, charts/export same query.
- Environment isolation: COMPOSE_PROJECT_NAME default derived from APP_PORT or explicit unique instance key + documented helper; isolated named volumes/networks and per-instance sessions, no hardcoded container names, host port once.
